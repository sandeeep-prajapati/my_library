# Extending Doctrine Entities from Third-Party Bundles

Directly editing vendor entities is fragile. Extend through supported mapping and composition patterns.

## 1) Safe Strategies

- Side-table with one-to-one relation
- Doctrine listeners for computed fields
- Custom repository over vendor repository
- MappedSuperclass/traits when vendor supports extension

## 2) Side-Table Pattern

Create your entity linked to vendor entity:

```php
#[ORM\Entity]
class ProductExtension
{
    #[ORM\OneToOne(targetEntity: VendorProduct::class)]
    #[ORM\JoinColumn(nullable: false, onDelete: 'CASCADE')]
    private VendorProduct $product;
}
```

## 3) Why This Works

- Keeps upgrade path clean.
- Your schema evolves independently.
- No collision with vendor migrations.

## 4) Common Mistakes

- Copying vendor entity class and trying to "override" mapping.
- Injecting custom fields into unmanaged metadata without tests.

## 5) Best Practices

- Keep extension data in dedicated bounded context.
- Write migration assertions for relation integrity.

## 6) Quick Recap

Use composition and supported metadata extension points; avoid forking entity definitions.
