# Global Response Modification with EventSubscriber

Global response interception is ideal for security headers, trace IDs, and uniform API metadata.

## 1) Subscriber Example

```php
namespace App\EventSubscriber;

use Symfony\Component\EventDispatcher\EventSubscriberInterface;
use Symfony\Component\HttpKernel\Event\ResponseEvent;
use Symfony\Component\HttpKernel\KernelEvents;

final class GlobalResponseSubscriber implements EventSubscriberInterface
{
    public static function getSubscribedEvents(): array
    {
        return [KernelEvents::RESPONSE => ['onResponse', 0]];
    }

    public function onResponse(ResponseEvent $event): void
    {
        if (!$event->isMainRequest()) {
            return;
        }

        $response = $event->getResponse();
        $response->headers->set('X-App-Version', '1.0');
        $response->headers->set('X-Content-Type-Options', 'nosniff');
    }
}
```

## 2) Why `isMainRequest()` Matters

Symfony can process sub-requests (fragments). Global headers should usually be applied only once.

## 3) Real-World Extensions

- Add correlation ID for distributed tracing.
- Normalize cache headers by route class.
- Add API deprecation warnings.

## 4) Common Mistakes

- Mutating binary/file responses incorrectly.
- Replacing cache headers blindly.

## 5) Best Practices

- Keep header logic idempotent.
- Add functional tests that assert final headers.

## 6) Quick Recap

`kernel.response` subscribers are the cleanest place for app-wide response policies.
