# Designing an Akeneo-Style Background Job System with Messenger

Import/export pipelines need resumability, status tracking, and retry-safe processing.

## 1) Job Model

Use two layers:
- `Job` (high-level workflow: import catalog)
- `JobStep` (chunked execution units)

Persist status, progress, timestamps, error summary.

## 2) Execution Pattern

1. API creates job record.
2. Dispatch `StartJobMessage(jobId)`.
3. Handler dispatches chunk step messages.
4. Steps update progress atomically.
5. Finalizer marks completed/failed.

## 3) Why Chunking Matters

Chunking avoids memory spikes and allows retrying only failed segments.

## 4) Retry/Failure Strategy

- Retry transient errors with backoff.
- Send permanent errors to failure transport.
- Expose "retry failed step" admin action.

## 5) Common Mistakes

- Long single handler doing entire import.
- No concurrency guard, causing duplicate running jobs.

## 6) Best Practices

- Add job lock per resource.
- Store normalized error payloads.
- Emit domain events for UI progress updates.

## 7) Quick Recap

Treat background jobs as state machines backed by messages, not as one giant worker function.
