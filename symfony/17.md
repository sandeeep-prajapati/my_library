# Testing Customized Symfony Systems

When you override core services, tests must prove both behavior and wiring.

## 1) Test Layers

- Unit tests for decorators/subscribers/voters
- Integration tests for container wiring
- Functional tests for end-to-end request flow

## 2) Container Wiring Test

Assert your decorated service is actually active:

```php
self::bootKernel();
$service = static::getContainer()->get(MailerInterface::class);
self::assertInstanceOf(AuditedMailer::class, $service);
```

## 3) Functional Override Test

Send HTTP request and assert:
- response headers from subscriber
- auth decisions from voter
- transformed exception payload

## 4) Regression Coverage

For each customization, add at least one "would fail without override" test.

## 5) Common Mistakes

- Only unit-testing custom class in isolation.
- Not testing service priority/order conflicts.

## 6) Best Practices

- Snapshot key response contracts.
- Run tests against production-like cache/container build.

## 7) Quick Recap

Customized Symfony code needs wiring-aware tests, not only business logic unit tests.
