# Symfony Messenger for Async Processing

Messenger turns expensive work into queued messages for reliability and scalability.

## 1) Core Pieces

- Message DTO
- Handler
- Transport (Doctrine/Redis/RabbitMQ/SQS)
- Worker
- Retry and failure transport

## 2) Minimal Flow

```php
$bus->dispatch(new SendInvoiceEmail($orderId));
```

Handler:

```php
#[AsMessageHandler]
final class SendInvoiceEmailHandler { /* ... */ }
```

## 3) Reliability Setup

- Configure retry strategy (max retries + delay)
- Use failure transport for poison messages
- Add idempotency in handlers

## 4) Operational Practices

- Run workers under Supervisor/systemd.
- Expose queue depth and failure metrics.
- Graceful deploy: stop workers, deploy, restart workers.

## 5) Common Mistakes

- Non-idempotent handlers causing duplicate side effects.
- Huge payloads in message body.

## 6) Best Practices

- Put only identifiers in messages.
- Rehydrate state in handler from DB.
- Separate command vs event buses when complexity grows.

## 7) Quick Recap

Messenger gives async throughput and resilience, but only if handlers are idempotent and observable.
