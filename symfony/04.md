# Overriding Core Behavior Safely in Symfony

You can change framework or vendor behavior without editing `vendor/` by using official extension points.

## 1) Safe Override Tools

- Service decoration
- Event subscribers/listeners
- Compiler passes
- Interface-based replacement

## 2) Service Decoration First

```yaml
services:
  App\Mailer\AuditedMailer:
    decorates: mailer
    arguments: ['@App\Mailer\AuditedMailer.inner']
```

Decorator keeps original behavior and adds yours around it.

## 3) Event-Based Behavior Injection

Use subscribers when behavior is request/response lifecycle dependent.

```php
final class RequestAuditSubscriber implements EventSubscriberInterface
{
    public static function getSubscribedEvents(): array
    {
        return [KernelEvents::REQUEST => 'onRequest'];
    }
}
```

## 4) Compiler Pass for Build-Time Rewiring

At container compile time, you can replace arguments, tag services, or register handlers dynamically.

## 5) Common Mistakes

- Hard replacing services with incompatible contracts.
- Using subscribers for pure domain logic.
- Doing heavy runtime reflection in hot paths.

## 6) Best Practices

- Prefer decoration before replacement.
- Keep overrides focused and testable.
- Document every override with reason and blast radius.

## 7) Quick Recap

Safe overrides are explicit and reversible. Decoration + events + compiler passes are the enterprise-safe stack.
