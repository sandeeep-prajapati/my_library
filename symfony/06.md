# Extending Third-Party Symfony Apps Safely

When integrating with an app you do not own, treat it as a platform, not as editable source.

## 1) Extension Layers

- Config overrides (`packages/*.yaml`)
- Service decoration/rebinding
- Event subscribers
- Custom bundle/plugin injection

## 2) Recommended Workflow

1. Identify target behavior.
2. Locate existing extension point.
3. Implement adapter/decorator.
4. Add integration test against upstream contract.

## 3) Example: Extending a Vendor Service

```yaml
App\Decorator\VendorPricingDecorator:
  decorates: vendor.pricing_calculator
  arguments: ['@App\Decorator\VendorPricingDecorator.inner']
```

## 4) Data Layer Extension

Prefer mapped superclasses, traits, listeners, or side tables instead of patching vendor entities directly.

## 5) Common Mistakes

- Copy-pasting vendor classes into app namespace.
- Replacing private internal services blindly.
- Skipping upgrade tests.

## 6) Best Practices

- Keep custom code in separate namespace/bundle.
- Track every override in one inventory doc.
- Test major vendor upgrades on staging with fixtures.

## 7) Quick Recap

Use extension points as contracts. If customization depends on internals, isolate it and test it hard.
