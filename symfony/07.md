# Symfony Kernel Events and Real Use Cases

Symfony's event system lets you intervene at specific lifecycle points.

## 1) Key Events

- `kernel.request`: routing, locale, tenant resolution
- `kernel.controller`: controller-level guards
- `kernel.controller_arguments`: argument normalization
- `kernel.view`: transform non-Response return values
- `kernel.response`: headers/cookies/caching
- `kernel.exception`: global error mapping
- `kernel.terminate`: post-response async-ish tasks

## 2) Practical Mapping

- Multi-tenant context: `kernel.request`
- Feature flag denial: `kernel.controller`
- JSON wrapper response: `kernel.view`
- Security headers: `kernel.response`
- Domain exception to API error: `kernel.exception`

## 3) Event Priority

Higher priority runs first. Use priorities carefully to avoid order bugs.

## 4) Common Mistakes

- Heavy DB work in `kernel.request`.
- Business rules in response listeners.
- Catch-all exception listener hiding useful stack traces in dev.

## 5) Best Practices

- Keep listeners thin; call services for real work.
- Make event usage explicit and documented.
- Prefer subscribers over scattered listeners for maintainability.

## 6) Quick Recap

Events are lifecycle hooks. Use the right hook for the right concern, and keep flow predictable.
