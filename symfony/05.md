# Building a Plugin System in Symfony

A plugin system is controlled extensibility: third-party modules can register behavior without touching core.

## 1) Core Architecture

Define plugin contracts:
- `PluginInterface` for metadata and boot hooks
- Tagged services for capabilities
- Event bus for loose coupling

## 2) Minimal Plugin Contract

```php
interface PluginInterface
{
    public function name(): string;
    public function boot(): void;
}
```

## 3) Registration via Service Tags

```yaml
App\Plugin\CsvImportPlugin:
  tags: ['app.plugin']
```

Compiler pass collects all `app.plugin` services into a `PluginRegistry`.

## 4) Runtime Flow

1. Container builds plugin list.
2. Registry validates compatibility/version.
3. Kernel boot calls plugin `boot()`.
4. Plugin contributes handlers/listeners/routes.

## 5) Safety Rules

- Version constraints per plugin.
- Capability checks before enabling hooks.
- Soft-fail broken plugin, do not crash whole app.

## 6) Best Practices

- Keep plugin API small and stable.
- Publish clear lifecycle hooks.
- Add contract tests for plugin boundaries.

## 7) Quick Recap

In Symfony, plugin systems are usually tags + registry + events + strict contracts.
