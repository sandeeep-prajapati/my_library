# Optimizing Heavy Symfony Applications

Performance work is a system problem: HTTP, container, DB, cache, and async pipeline all matter.

## 1) Profiling First

Start with Symfony profiler/Blackfire/APM before changing code.

## 2) High-Impact Areas

- Doctrine query count and N+1
- Cache strategy (result cache, HTTP cache, Redis)
- Serializer overhead
- Excessive autowired cold paths

## 3) Doctrine Optimization

- Fetch joins where correct
- Read-model queries for list screens
- Batch writes and clear EM in loops

## 4) Cache Strategy

- HTTP: `ETag`, `Cache-Control`, reverse proxy
- App: Redis for hot computed data
- Config/container warmup on deploy

## 5) Async Offloading

Move slow side effects (emails, webhooks, indexing) to Messenger workers.

## 6) Common Mistakes

- Premature micro-optimizations.
- Global cache with no invalidation plan.

## 7) Best Practices

- Set SLOs and track p95 latency.
- Add load testing for critical endpoints.
- Optimize one bottleneck at a time.

## 8) Quick Recap

Heavy Symfony apps become fast when query load, cache policy, and async boundaries are designed intentionally.
