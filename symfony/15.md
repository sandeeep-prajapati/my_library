# Building a Modular API Layer in Symfony

A scalable API layer separates transport concerns from domain logic.

## 1) Layered API Shape

- Controller: HTTP mapping only
- Application service: use-case orchestration
- Domain service/entity: business rules
- DTO/Transformer: response contracts

## 2) Versioning Strategy

Use URI or header versioning and keep per-version transformers.

```text
/api/v1/products
/api/v2/products
```

## 3) Extensibility Hooks

- Tagged normalizers/transformers
- Serializer groups per client capability
- Event hooks for request/response enrichment

## 4) Integration Readiness

Add:
- pagination defaults
- idempotency for writes
- stable error format (`code`, `message`, `details`)

## 5) Common Mistakes

- Returning Doctrine entities directly.
- Breaking clients by changing response shape silently.

## 6) Best Practices

- Treat API schema as contract.
- Add backward compatibility tests.
- Use deprecation headers before removal.

## 7) Quick Recap

Modular APIs in Symfony rely on strict boundaries, versioned contracts, and explicit transformers.
