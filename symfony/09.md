# Doctrine Internals: Unit of Work, Identity Map, Proxies

Doctrine behaves like an object graph manager, not just a query builder.

## 1) Unit of Work

`UnitOfWork` tracks entity states:
- NEW
- MANAGED
- REMOVED
- DETACHED

`flush()` computes change sets and executes SQL in transaction-aware order.

## 2) Identity Map

Within one EntityManager, same DB row maps to one in-memory object instance. This avoids duplication and inconsistent state.

## 3) Proxy Objects

Lazy-loading relations are proxies that load data only when accessed.

```php
$order = $em->find(Order::class, 1); // customer relation can be proxy
$name = $order->getCustomer()->getName(); // triggers lazy load
```

## 4) Customization Points

- Doctrine events/listeners/subscribers
- Custom DBAL types
- Repository abstractions for query policies
- Filters for multi-tenant/soft-delete logic

## 5) Common Mistakes

- Huge unit-of-work in one request.
- N+1 query explosions.
- Using detached entities without merge strategy.

## 6) Best Practices

- Use fetch joins and batch processing.
- Clear EntityManager in long-running jobs.
- Measure SQL with profiler before optimization.

## 7) Quick Recap

Understand UnitOfWork + IdentityMap first; most Doctrine behavior and performance issues become explainable after that.
