# Custom Authentication in Symfony Security

Modern Symfony security is authenticator-based and highly composable.

## 1) Building Blocks

- User provider (load user)
- Authenticator (credentials -> passport)
- Firewall (where auth applies)
- Voters (authorization decisions)

## 2) Custom Authenticator Skeleton

```php
final class ApiTokenAuthenticator extends AbstractAuthenticator
{
    public function supports(Request $request): ?bool
    {
        return $request->headers->has('X-API-Token');
    }
}
```

Then create `Passport` with `UserBadge` and credentials validation.

## 3) Firewall Setup

```yaml
security:
  firewalls:
    api:
      pattern: ^/api
      stateless: true
      custom_authenticators:
        - App\Security\ApiTokenAuthenticator
```

## 4) Voters for Domain Rules

Use voters for context-aware authorization, not controller `if` chains.

## 5) Common Mistakes

- Mixing auth and authorization logic.
- Performing heavy DB lookups in every voter without caching.

## 6) Best Practices

- Keep authenticator deterministic and fast.
- Return explicit failure responses for API clients.
- Test firewall + authenticator + voter path together.

## 7) Quick Recap

In Symfony, authentication proves identity; voters decide permissions. Keep these layers clean.
