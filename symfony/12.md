# Dynamic Access Control Overrides in Large Systems

Static roles are rarely enough in enterprise apps. You often need context-aware policies.

## 1) Dynamic Access Model

Combine:
- Role baseline (`ROLE_ADMIN`)
- Context attributes (tenant, ownership, workflow state)
- Policy services or voters

## 2) Voter + Policy Service Pattern

Controller calls:

```php
$this->denyAccessUnlessGranted('PRODUCT_EDIT', $product);
```

Voter delegates rule complexity to a policy service.

## 3) Runtime Policy Sources

- Database-managed permission toggles
- Feature flags
- Tenant-specific policy matrices

Cache policy snapshots to avoid per-request recomputation.

## 4) Common Mistakes

- Encoding dynamic rules directly in YAML `access_control`.
- Hidden bypasses in admin-only routes.

## 5) Best Practices

- Keep policy decision pure and auditable.
- Add decision logging for sensitive actions.
- Add deny-by-default fallback.

## 6) Quick Recap

Dynamic access control belongs in voters/policies, with role checks as only one input.
